# 3. Project 생성



## 1) Namespace 생성



```sh

$ kubectl create ns edu00
  kubectl create ns edu00-dev
  kubectl create ns edu00-prd

```





## 2) Project 생성

sourceRepos 에 자신의 repository 를 설정한다.

```sh

$ cat <<EOF | kubectl -n argocd-system apply -f -
apiVersion: argoproj.io/v1alpha1
kind: AppProject
metadata:
  name: pedu00
  namespace: argocd-system
spec:
  description: "edu00 project"
  sourceRepos:
    - https://github.com/rohansong/SampleJava.git
  destinations:
    - namespace: edu00
      server: https://kubernetes.default.svc
    - namespace: edu00-dev
      server: https://kubernetes.default.svc
    - namespace: edu00-prd
      server: https://kubernetes.default.svc
  clusterResourceWhitelist:
    - group: "*"
      kind: "*"
EOF


```

* sourceRepos
  * 자신의 repository 를 설정한다.
* destinations
  * 프로젝트가 배포될 Server 와 Namespace 를 지정한다.





# 4. ArgoCD Application 등록

ArgoCD Application을 등록하려면 선언적 구성 파일을 작성하고 이를 적용한다.

기 생성된 Project에 애플리케이션을 구성한다.



## 1) DEV 환경 배포

* 저장소 : https://github.com/rohansong/SampleJava
* kustomization.yaml  : manifests/overlays/dev/

```sh

$ cat <<EOF | kubectl -n argocd-system apply -f -
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: edu00-samplejava-dev
  namespace: argocd-system
spec:
  project: pedu00
  source:
    repoURL: 'https://github.com/rohansong/SampleJava.git'
    targetRevision: main
    path: manifests/overlays/dev
  destination:
    name: in-cluster
    namespace: edu00-dev
  syncPolicy: {} # Mannual Sync Mode
  #syncPolicy:   # Auto Sync Mode
  #  automated:
  #    prune: true                # Git에서 삭제된 리소스 자동 제거
  #    selfHeal: true             # 실시간 drift 자동 복원
EOF


# 확인
$ kubectl -n argocd-system get Application
NAME                   SYNC STATUS   HEALTH STATUS
edu00-samplejava-dev   OutOfSync     Missing


# OutOfSync 상태이므로 ArogoCD Web 에서 Sync 버튼을 클릭한다.
# Auto-sync 일 경우 Sync 주기(기본값:3분)가 있음

```

* source
  * https://github.com/rohansong/SampleJava.git  repo에 `manifests/overlays/dev` 라는 path 에는 dev 환경에 배포되어야 할 yaml 들이 선언되어 있다.
* destination
  * 자신 Cluster 내 edu00-dev Namespace 에 application을 배포한다.



### 삭제시...

```sh

# application 삭제시... (detach)
$ kubectl -n argocd-system delete Application edu00-samplejava-dev

```

* delete Application 명령은 **Git 관리 대상 리소스만 해제(detach)** 만 진행한다.

  * 즉, application는 삭제되더라도 application 에 의해서 생성된 리소스들(pod 등)는 삭제되지 않는다.

  * 만약 Application 삭제시 해당 리소스를 같이 삭제하기를 원한다면 아래와 같이 cascade 명령을 사용해야 한다.

    * ```sh
      $ argocd app delete --cascade
      ```

# 5. Application Version Up

## 1) DEV 환경 배포

DEV CI 작업을 수행한후 CD 작업을 수행해보자.



### (1) CI 작업 수행

기 생성되어 있는 CI workflow 를 수행한다.

* 메뉴 : Actions > cont-ci-50 클릭 

* runs-on 수정

  * Github-hosted runner 로 수정후 수행

  * ```yaml
    ...
    
    jobs:
      build:
        runs-on: ubuntu-latest   # Github-hosted
        # runs-on: self-hosted           # VM
        # runs-on: edu00-arc-runner-set  # AKS
        
    ```

* Run workflow 클릭

  * DEV 선택

* 실행되는 workflow 클릭 및 로그 확인

  

### (2) CD 작업 수행

* CI workflow 작업이 완료되면 마지막 단계에서 tag 버젼을 update 한다. 
* 이로 인해 ArgoCD Application 은 원본소스와 내용이 달라지므로 `Out of sync` 형태로 변한다.
* `sync` 버튼을 클릭함으로서 신규 버젼이 K8s 에 반영된다.



## 2) PRD 환경 배포

PRD CI 작업을 수행한후 CD 작업을 수행해보자.

수행 매커니즘은 위 DEV 와 동일하다.

1. **CI 작업 수행**

2. **CD 작업 수행**
